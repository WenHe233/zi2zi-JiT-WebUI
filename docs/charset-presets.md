# Character preset design

The WebUI stores character presets as Unicode code points. Legacy encodings
such as GBK, Big5, JIS and KS X 1001 are compatibility selectors, not byte
storage formats. Multiple presets are deduplicated before generation.

## Presets

| Group | Presets | Notes |
|---|---|---|
| Base | `latin-ascii`, `latin-western`, `latin-extended`, `latin-full-european`, `cjk-punctuation`, `symbols-common` | Small reusable building blocks |
| Simplified Chinese | `zh-Hans-3500`, `zh-Hans-6500`, `zh-Hans-8105`, `zh-Hans-GBK` | The first three preserve the official table order and levels |
| Traditional Chinese | `zh-Hant-TW-4808`, `zh-Hant-TW-extended`, `zh-Hant-Big5`, `zh-Hant-HK-HKSCS` | Taiwan common, practical extended, encoding compatibility and Hong Kong coverage |
| Japanese | `ja-basic`, `ja-jis0208`, `ja-jis0213`, `ja-cp932` | `ja-basic` includes kana, punctuation and 2,136 Jōyō kanji |
| Korean | `ko-ksx1001` | Deterministic EUC-KR/KS X 1001 mapping |
| Combined | `east-asia-complete` | GBK ∪ Big5-HKSCS ∪ JIS X 0213 ∪ KS X 1001 |

The default selection is `latin-extended + cjk-punctuation +
zh-Hans-6500`. Every selector in the WebUI shows its source, purpose and
incremental deduplicated count.

`zh-Hant-TW-extended` is deliberately described as a *practical extended
set*: it is the union of the official 4,808 common-character list and the
Big5 mapping. It must not be presented as a verbatim copy of the Ministry's
less-common character table.

## Sources and reproducibility

- The 8,105 Simplified Chinese code points are digitized from the 2013
  *Table of General Standard Chinese Characters*. The first 3,500 entries are
  level 1; the first 6,500 are levels 1 and 2.
- Taiwan's 4,808 list is extracted from the ODS published by the Ministry of
  Education at
  <https://language.moe.gov.tw/material/info?m=9fe3ff5a-5a8c-4817-9e60-6337dd55a509>.
- The 2,136 Jōyō kanji follow the 2010 Agency for Cultural Affairs table. The
  vendored list is cross-checked against the CJKVI table.
- Encoding presets are generated by exhaustively decoding the relevant
  one- and two-byte sequences with Python's named codec. They therefore do
  not depend on the operating-system locale.

Each vendored list is one `U+XXXX` code point per line. Tests lock the
expected unique counts.

## Regional output

When more than one regional preset is selected, the WebUI can produce
separate SC, TC, JP and KR fonts. A model receives glyph structure from the
content/source fonts, so users may assign an ordered font collection to each
region. For each code point, the first covering regional font wins, followed
by the ordered global fallback collection. This supports split collections
such as Jigmo without merging beyond the TrueType glyph limit. Fallback
coverage alone does not create authentic regional variants for overlapping
Unicode code points, so preferred regional fonts should come first.

The optional merged-font mode requires a primary region. Regional splitting
is the default.

## TrueType glyph limit

`maxp.numGlyphs` is an unsigned 16-bit value. `.notdef` and any future
alternate glyphs also consume glyph IDs, so the builder validates the final
glyph order and rejects fonts above 65,535 glyphs.
